# MaintKit Development Process

## Selected Process Model

MaintKit will use Scrum as its Agile development process. Since MaintKit is a solo project, I will adapt Scrum to an individual development environment while still using a product backlog, prioritized user stories, sprints, sprint goals, and incremental development. This approach will allow me to develop the application in manageable pieces and adjust requirements as I learn more about how the application should function.

## GitHub Project Board

The MaintKit Development GitHub Project board is used to organize and track the project backlog. User stories move through three statuses:

- Backlog
- In Progress
- Done

Project Board: [MaintKit Development] https://github.com/users/thomasgross23/projects/1/views/1

## Product Backlog

The initial product backlog contains eight user stories:

1. Search for equipment by ID or name
2. View equipment information
3. Select maintenance task
4. View required tools
5. Generate tool checklist
6. Manage equipment records
7. Associate tools with maintenance tasks
8. Identify required vs. recommended tools

## Sprint 1

**Length:** 2 weeks (September 25 - October 8)

**Sprint Goal:** Establish the core MaintKit workflow by allowing a maintenance technician to locate equipment, view its information, select a maintenance task, and identify the tools required for that task.

### Sprint 1 Backlog

- #1 Search for equipment by ID or name
- #2 View equipment information
- #3 Select maintenance task
- #4 View required tools

The remaining product backlog items will remain available for future sprints and can be reprioritized as the project develops.
